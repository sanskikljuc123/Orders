# PR ready (Orders)

Goal: a pull request that is green on the first CI run and says truthfully what it does. Follow the
steps in order; stop and report at the first failure instead of working around it.

## 1. Branch and scope
- `git fetch origin main`. If the branch's last PR was merged, restart from `origin/main` and move
  only the new commits onto it (never stack on merged history).
- `git status` clean except the intended change; `git log origin/main..HEAD` lists only this
  change's commits. Untracked files: commit or ask, never leave them out silently.

## 2. Gates (choose by what changed; run, then show the real summaries)
| Changed | Run |
|---|---|
| any code | `./build.sh --target Conventions UnitTests ContractTests IntegrationTests CoverageGate` (needs Docker) |
| UI, `wwwroot`, E2E | also `dotnet test tests/Orders.E2E` (cloud container: `E2E_CHROMIUM_PATH`, `E2E_VIDEO=0`) |
| `OrderService`, `SessionStore`, `CreateOrderValidator`, `Payments.cs` | also `./build.sh --target Mutation` (break thresholds in `stryker/*.json`) |
| `deploy/`, chart, AppHost, images | also `./build.sh --target Helm` |
| API endpoints or responses | `OpenApiContractTests`; if the change is intended, update the snapshot (CLAUDE.md, Commands) and review its diff |

A gate that fails is fixed at its cause; never lower a floor, skip or loosen a test.

## 3. Definition of done (CLAUDE.md)
Check each item and name the evidence: new behaviour has a test that was seen failing when the
behaviour was broken; `TESTING.md` rows and the endpoint matrix are updated; "How it works now"
matches the code; commit messages carry no AI attribution (the hook and `Conventions` enforce it).

## 4. Independent review
Run the `pr-review` agent on `origin/main...HEAD`. Fix what it marks as blocking (with a test where
it is behaviour), or explain to the user why not. Its findings are a second opinion, not orders.

## 5. Ask, then push and open the PR
Show the user: the commits, the gate results, the review verdict, and a draft PR description
(what changed and why, how it was verified, what is still open). **Wait for an explicit OK.** Then:
`git push -u origin <branch>`, create the PR with that description, read it back and remove any
footer the tool appended ("Generated by Claude Code"), and offer to watch CI.
